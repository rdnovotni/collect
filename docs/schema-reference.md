# Schema reference

A field-by-field reference for the Collect v0.1 core, generated by hand from [`schema/0.1/common.schema.json`](../schema/0.1/common.schema.json), [`schema/0.1/record.schema.json`](../schema/0.1/record.schema.json), and [`schema/0.1/profile.schema.json`](../schema/0.1/profile.schema.json). This is the day-to-day lookup table; [`spec/core.md`](../spec/core.md) is the normative text, and [architecture.md](architecture.md) explains the *why* behind these choices.

If this page and the schema files disagree, the schema files (and the tests in `tests/`) are authoritative — please [open an issue](https://github.com/rdnovotni/collect/issues).

## Every record

Every record is a JSON object with these three fields required:

| Field | Type | Notes |
|---|---|---|
| `collect` | `const "0.1"` | The core spec version. |
| `id` | [id](#id) | Unique. See [`spec/core.md` §4](../spec/core.md#4-identifiers). |
| `layer` | enum | One of `work`, `catalog`, `variant`, `instance`, `collection`. |

## Building-block types

These are the shapes reused across many fields. Names in `code` match `$defs` in `common.schema.json`.

### `id`
A compact identifier `prefix:path` (e.g. `example:catalog/pc7421`) or an absolute URI. Pattern: `^[A-Za-z][A-Za-z0-9+.-]*:\S+$`. `local:` is reserved for identifiers meaningful only inside one person's collection; tools must not assume `local:` ids are globally unique.

### `ref`
Same shape as `id` — a pointer to another record's `id`. Used by `instanceOf`, `variantOf`, `work`, relationship `target`, and collection entry `ref`.

### `edtf`
A date in [Extended Date/Time Format](https://www.loc.gov/standards/datetime/). Supported forms:

| Form | Example |
|---|---|
| Year / month / day | `1906`, `1906-07`, `1906-07-14` |
| Unspecified digits | `190X`, `19XX`, `1906-XX` |
| Uncertain / approximate / both | `1906?`, `1906~`, `1906%` |
| Interval (either end open) | `1905/1915`, `1907/..`, `../1915` |

### `slug`
A lowercase-hyphenated vocabulary term, e.g. `publisher`, `same-image-as`. Pattern: `^[a-z0-9]+(?:-[a-z0-9]+)*$`.

### `text`
A non-empty string.

### `agent`
A person or organization and the role they played.

| Field | Type | Required | Notes |
|---|---|---|---|

| `name` | text | ✓ | |
| `id` | ref | | Link to an agent record or external id (e.g. `wikidata:Q42`). |
| `identifiers` | list of [identifier](#identifier) | | |
| `note` | string | | |

|---|---|---|
| `scheme` | slug — see [`vocab/identifier-schemes.json`](../vocab/identifier-schemes.json) | ✓ |
| `value` | text | ✓ |
| `note` | string | |

| Field | Type |
|---|---|

### `price`

A grade on a named scale (see [`vocab/condition-scales/`](../vocab/condition-scales/)). Unlike other vocabularies, a value not on a *known* scale is an **error**, not a warning — see [architecture.md §4](architecture.md#4-why-the-validator-treats-vocabularies-as-open-lists).

| Field | Type | Required |
|---|---|---|

| `note` | string | |

| Field | Type |
|---|---|

## Fields on every layer (`baseRecord`)

In addition to `collect`, `id`, `layer`:

| Field | Type |
|---|---|
| `category` | slug — see [`vocab/categories.json`](../vocab/categories.json) |
| `title` | text |
| `description` | string |
| `date` | edtf |
| `agents` | list of [agent](#agent) |
| `identifiers` | list of [identifier](#identifier) |
| `places` | list of [place](#place) |
| `images` | list of [image](#image) |
| `relationships` | list of [relationship](#relationship) |
| `sources` | list of [source](#source) |
| `tags` | list of unique strings |
| `notes` | string |
| `meta` | [meta](#meta) |

Any other top-level key must either be a layer-specific field below or a profile field `profileId:fieldName` — unknown plain keys are an error.

## Layer-specific fields

### `work`
No extra fields beyond the base record.

### `catalog`
| Field | Type | Notes |
|---|---|---|
| `work` | ref → `work` | The work this item reproduces, if known. |
| `number` | string | Position within the set/series (paired with a `part-of` relationship to the set). |

### `variant`
Requires `variantOf`.

| Field | Type | Required | Notes |
|---|---|---|---|
| `variantOf` | ref → `catalog` | ✓ | |
| `variantType` | slug — see [`vocab/variant-types.json`](../vocab/variant-types.json) | | |

### `instance`
| Field | Type | Notes |
|---|---|---|
| `instanceOf` | ref → `catalog` or `variant` | Optional — an uncataloged object omits it and describes itself directly. |
| `quantity` | integer ≥ 1 | Default 1. |
| `status` | slug — see [`vocab/instance-statuses.json`](../vocab/instance-statuses.json) | |
| `condition` | list of [condition](#condition) | |
| `acquired` | object: `date` (edtf), `price` ([price](#price)), `from`, `venue`, `note` | **Private by default.** |
| `provenance` | list of `{ event (slug), date (edtf), party, note }` | Ownership/custody history, oldest first. `event` examples: `acquired`, `sold`, `gifted`, `inherited`, `graded`, `exhibited`. |
| `storage` | string | **Private by default.** Where the object is kept. |

### `collection`
Requires `entries`.

| Field | Type | Notes |
|---|---|---|
| `owner` | string | |
| `purpose` | slug | `have`, `want`, `trade`, `checklist`... |
| `entries` | list of `{ ref (required), quantity, note }` | Points at catalog items or instances. |

## Reference-field targets

The validator checks that these fields point at the right kind of record:

| Field | Must point at layer |
|---|---|
| `instanceOf` | `catalog` or `variant` |
| `variantOf` | `catalog` |
| `work` | `work` |

`relationships[].target` and `entries[].ref` are not layer-restricted.

## Profile fields

A profile field is a top-level key `profileId:fieldName` (pattern: `^[a-z][a-z0-9-]*:[a-z][A-Za-z0-9]*$`). Its own schema, allowed layers, and optional vocabulary are declared once in the profile's `profile.json` — see [`spec/profiles.md`](../spec/profiles.md) for how to define one.

### `postcard` profile (v0.1.0)

Source: [`profiles/postcard/0.1.0/profile.json`](../profiles/postcard/0.1.0/profile.json).

| Field | Layers | Type | Vocabulary |
|---|---|---|---|
| `postcard:era` | catalog, variant, instance | string | [`vocab/eras.json`](../profiles/postcard/0.1.0/vocab/eras.json) |
| `postcard:format` | catalog, variant, instance | string | [`vocab/formats.json`](../profiles/postcard/0.1.0/vocab/formats.json) |
| `postcard:printProcess` | catalog, variant, instance | string | [`vocab/print-processes.json`](../profiles/postcard/0.1.0/vocab/print-processes.json) |
| `postcard:stampBox` | catalog, variant, instance | non-empty string | — |
| `postcard:posted` | instance | boolean | — |
| `postcard:postmark` | instance | object: `date` (edtf), `place`, `note` | — |
| `postcard:postage` | instance | non-empty string | — |
| `postcard:message` | instance | string | — |

Fields that make sense on a cataloged item (`era`, `format`, `printProcess`, `stampBox`) are also allowed directly on `instance`, so an uncataloged postcard can be described fully without a catalog record to hang those fields off of.

## Private data

`acquired`, `storage`, and any profile field marked `"private": true` in its `profile.json` entry are personal information. Tools should exclude these from anything published or shared unless the owner explicitly opts in — see [`spec/core.md` §10](../spec/core.md#10-private-data).
